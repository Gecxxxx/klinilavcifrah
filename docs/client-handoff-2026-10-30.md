## Заявки и Telegram

`/kontakty#forma` → `POST /api/leads` → SQLite `/var/lib/kvc-leads/leads.sqlite3` → отдельная очередь → Telegram. Подтверждение формы выдаётся после записи в SQLite, независимо от доставки уведомления.

Бот: https://t.me/klinilavcifrah_bot. Получатель подключается в личном чате через `/start`, проверяет состояние через `/status`, отключается через `/stop`. Подписка хранится на VPS и переживает публикации. При отсутствии подписчиков заявки остаются в очереди. Доставка обычно выполняется ближайшим минутным запуском таймера.

С 01.11.2026 подписка и доставка ограничиваются закрытым `TELEGRAM_ALLOWED_CHAT_IDS` в `/etc/kvc-leads.env`. Действующий получатель сохранён. Нового получателя оператор сначала добавляет в этот список на сервере, затем перезапускает API; получатель отправляет `/start`. Неизвестный аккаунт не получает доступ по одному `/start`. При отзыве доступа ID удаляется из списка, API перезапускается; следующие запуски очереди также исключают этот ID из повторной доставки. Значения ID и токены в GitHub не публикуются. Внешние коммерческие контакты сайта ведут в общую форму и к согласованному номеру руководителя.

Доступ к полному реестру — из личного root-сеанса. `kvc-leads stats` показывает сводку; `kvc-leads list` — ID и статусы без контактов. `kvc-leads export /var/lib/kvc-leads/export-private.jsonl` создаёт закрытый JSONL с полным содержимым, не перезаписывая существующий файл. Передавать такую выгрузку только владельцу защищённым способом. Публичной страницы чтения реестра нет.

Конфигурация интеграций: `/etc/kvc-leads.env`, root, 0600. Токены в документацию и GitHub не копировать. Таймеры: `kvc-leads-notify.timer`, `kvc-leads-backup.timer`; API: `kvc-leads-api.service`.

## Фактическая обработка данных

В реестре хранятся имя, клиника/компания, контакт, необязательные сайт и задача, время, ID, подтверждение согласия и его версия, страница/первый источник/UTM, служебные статусы. Для ограничения частоты обращений используется хеш IP. При доставке текст заявки и контакт передаются Telegram и подписанным получателям бота. Подписки и журнал доставки также хранятся в SQLite.

Ежедневные проверяемые SQLite-копии находятся в `/var/backups/kvc-leads`: до семи копий в пределах 64 MiB, либо одна последняя копия большего размера. Удаление старых обращений автоматически не настроено. 01.11 создан полный закрытый снимок сайта, API, конфигурации, TLS и согласованной копии SQLite; проверенная по SHA-256 копия сохранена на компьютере технического администратора с доступом только локальному владельцу и SYSTEM. Страна физического хранения VPS и внешней копии, окончательные сроки хранения и порядок исполнения запросов на удаление/отзыв требуют подтверждения оператором. Эти факты не заменяются обещаниями на публичной странице.

В браузере используется sessionStorage для источника, выбранного направления и защиты от повторной отправки; исходные контакты и текст задачи туда не записываются. Контакты и текст обращения не передаются в параметры аналитических событий. 03.11.2026 владелец предоставил счётчик Яндекс Метрики 114039537; он закреплён в VPS workflow. Вебвизор, карта кликов и учёт ссылок включены. Форма скрыта от записи Вебвизором, содержимое полей помечено ym-disable-keys. VK Pixel не добавлялся.
