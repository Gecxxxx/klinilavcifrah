## Что проверяется автоматически по ссылке

`scripts/check-live.py`: 9 страниц и один H1 на каждой, уникальные metadata, canonical,
внутренние ссылки и якоря, POST вместо GET в каждой форме, alt у изображений,
robots/sitemap/OG/404, совпадение ревизий статики и OPTIONS API.
Запросы не создают лидов и не отправляют сообщений людям. После каждого успешного
деплоя запускается job verify_public; её результат виден в GitHub Actions.
Отдельно выводятся известные незакрытые контактные/юридические пункты.

## Проверки этой редакции

- Python: 36 проверок API/бота/native POST и 29 проверок публикации/операционных скриптов.
- Клиентская валидация: 6 проверок, requestId: 3 проверки; lint, TypeScript, статическая сборка и SEO-проверка.
- Chromium: основные сценарии формы, сохранение/повторы/ошибки, все 9 страниц на desktop/mobile;
  матрица ширин 320/360/390/430/1280/1440, автоматический axe на всех страницах.
  Проверки с отправкой используют временную SQLite без Telegram-токена.
- Шрифт переведён из TTF 371616 байт в WOFF2 169688 байт с проверкой одинаковых glyph cmap и вариативных осей.
  Zod Mini сохраняет правила формы; библиотека Motion заменена CSS-анимациями.
- Lighthouse запускался по 3 раза для mobile/desktop локальной сборки. Это лабораторная
  эмуляция, не полевой p75: мобильная цель LCP 2.5 s ещё не подтверждена.

## Однократная настройка сжатия на VPS (можно отложить)

Публичная проверка до публикации этой редакции обнаружила gzip для HTML, но не для JS.
`deploy/configure-compression.py` подготовлен для персонального root SSH: он меняет только
vhost KVC, сохраняет резервную копию, проверяет nginx и публичный JS, откатывает конфигурацию
при ошибке. Пользователь автодеплоя не имеет sudo; публикация приложения этот шаг не выполняет.
Не отмечать сжатие включённым до успешного запуска и проверки на основном домене.
